# Project Instructions

## Spec implementations

- Always create and work on a new branch before implementing a specification.
- Use a descriptive type-based prefix for implementation branches, such as `feat/`, `fix/`, or `docs/`.
- Do not implement a specification directly on `main` or another shared branch.

## Commits

- Follow the Conventional Commits specification for every commit.
- Use the format `<type>(<optional scope>): <description>`.
- Keep commit messages concise and use an imperative description.
- Use an appropriate type such as `feat`, `fix`, `refactor`, `test`, `docs`, `build`, `ci`, or `chore`.
